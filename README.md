# cc-ticket-api

工单处理服务。

保留现有业务代码与自动化测试，作为后续功能迭代的稳定起点。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 重复工单合并与受控撤销

服务支持将多张重复工单合并到一张主工单，并在满足条件时受控撤销。
合并采用「创建请求 → 确认」两阶段流程，相关接口位于 `/api/merges`。

### 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/merges` | 创建合并请求（待确认），按 `businessNo` 幂等 |
| GET | `/api/merges/{id}` | 查询合并请求详情（含快照与历史） |
| POST | `/api/merges/{id}/confirm` | 确认合并 |
| POST | `/api/merges/{id}/revoke` | 撤销合并 |
| GET | `/api/merges/master/{masterTicketId}` | 主工单聚合视图 |
| GET | `/api/merges/membership/{ticketId}` | 单张工单的合并归属查询 |

### 主要业务规则

#### 1. 参与工单校验

- 一次合并指定一张主工单（`masterTicketId`）和多张重复工单（`duplicateTicketIds`，不可为空、不可重复、不能包含主工单自身）。
- 所有参与工单必须存在且未删除，且尚未被其他活动合并（待确认或已确认）占用。
- 主工单不能已经是其他工单的重复项；重复工单不能已经作为主工单合并过其他工单。
- 合并关系不允许链式引用或循环（A→B、B→C 这类串联被拒绝）。

#### 2. 两阶段确认与原子性

- 创建请求时记录每张参与工单的版本号基线与请求内容。
- 确认在一次原子操作中完成：
  - 冻结所有重复工单（之后禁止更新、状态变更、加备注、删除）；
  - 将重复工单的备注与状态历史关联到主工单，可在聚合视图中统一查看；
  - 为每张参与工单记录合并前快照（关键字段 + 完整历史），用于撤销与审计。
- 确认时若任一参与工单在请求创建后发生过变化（版本号变化），或已被删除、被其他合并抢占，则**整次合并失败**：请求置为 `FAILED`、释放占用，不留下任何部分关系。
- 合并全程在互斥临界区内执行，多个请求并发合并同一工单时最多一个成功，其余返回 `409`。

#### 3. 业务号幂等

- `businessNo` 是幂等键：相同业务号、相同内容重复提交，直接返回首次结果（`idempotentReplay=true`），不会重复创建。
- 相同业务号但内容（主工单 / 重复工单集合 / 操作人）发生变化，返回 `409` 冲突。
- 对已确认合并重复调用确认、对已撤销合并重复调用撤销，均返回首次结果。

#### 4. 受控撤销

仅当同时满足以下条件时才允许撤销，否则返回 `409`：

- 合并处于已确认（`MERGED`）状态；
- 主工单尚未关闭（非 `CLOSED`）；
- 合并后没有新增任何处理记录（主工单或重复工单上无确认记录之后的新备注/系统记录）。

撤销会完整恢复各工单的独立状态：

- 解除冻结，重复工单恢复可编辑；
- 清除重复工单到主工单的归属与历史关联；
- 按合并前快照恢复重复工单状态；
- 移除确认时写入的系统记录，使历史回到合并前形态。

重复撤销返回首次撤销结果。合并与撤销的生命周期历史只允许追加、不可修改。

#### 5. 查询与错误处理

- 主工单聚合视图返回主工单、其重复工单列表，以及汇聚后的全部处理记录。
- 归属查询返回单张工单的角色：`MASTER`（主工单）、`DUPLICATE`（重复项，并给出 `masterTicketId`）、`INDEPENDENT`（未参与合并）。
- 状态冲突（占用、变化、不可撤销、幂等内容不一致等）统一返回 `409`；合并请求或工单资源不存在统一返回 `404`；参数校验失败返回 `400`。

### 合并请求状态流转

    PENDING ──confirm──► MERGED ──revoke──► REVOKED
       │                   │
       └──confirm(变化/抢占)─► FAILED        （释放占用，历史保留）
