# cc-ticket-api

工单处理服务。

保留现有业务代码与自动化测试，作为后续功能迭代的稳定起点。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run

## 重复工单合并与撤销

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/ticket-merges` | 创建合并请求（PENDING） |
| POST | `/api/ticket-merges/{id}/confirm` | 确认合并 |
| POST | `/api/ticket-merges/{id}/undo` | 撤销合并 |
| GET | `/api/ticket-merges/{id}` | 查询合并记录（含合并前快照） |
| GET | `/api/tickets/{id}/merge-view` | 主工单聚合视图（主工单 + 重复工单 + 归集后的全部处理记录） |
| GET | `/api/tickets/{id}/merge-belonging` | 单张工单的合并归属查询 |

创建合并请求体：

```json
{
  "businessKey": "MK-20260928-001",
  "primaryTicketId": 1,
  "duplicateTicketIds": [2, 3]
}
```

### 主要业务规则

1. **参与资格**：参与合并的工单必须存在且未删除；任一工单（无论作为主工单还是重复工单）同一时间只能属于一个进行中的合并关系。主工单不能是其他合并的重复项，其他合并的主工单也不能作为重复工单并入，从而杜绝链式引用与循环。
2. **两阶段确认**：合并请求创建后处于 PENDING，并记录各参与工单的版本（`updatedAt`）。确认时先校验所有参与工单在确认前未发生变化（未修改、未删除、未被其他合并占用），校验全部通过后在一次原子操作中：冻结重复工单的后续编辑、把重复工单的备注与状态历史关联到主工单、记录所有参与工单的合并前快照。任一工单在确认前发生变化，整次合并失败（状态置为 FAILED 终态），不留下任何部分关系。
3. **幂等与并发**：`businessKey` 为幂等业务号。相同业务号且内容（主工单 + 重复工单集合）一致的重复提交返回首次结果；内容不一致返回 409 冲突。合并写操作在同一临界区内完成校验与变更，多个请求并发合并同一工单时最多一个成功。
4. **受控撤销**：仅当主工单未关闭（非 CLOSED、未删除）且合并后主工单没有新增处理记录（备注/状态变更）时才允许撤销。撤销会把迁移的处理记录完整还原到原工单、解除重复工单的冻结，恢复各工单的独立状态与可编辑性。重复撤销返回首次撤销的结果，不产生重复变更。
5. **历史不可修改**：合并记录只能沿 `PENDING → MERGED → UNDONE`（或 `PENDING → FAILED`）推进，合并前快照、迁移记录与各阶段时间戳一旦写入即保留，不提供任何修改或删除入口。
6. **冻结约束**：被合并的重复工单禁止更新、变更状态、添加备注与删除；存在已生效合并关系的主工单同样禁止删除。
7. **错误处理**：资源不存在（工单/合并请求）统一返回 404；状态冲突（工单被占用、已冻结、幂等内容不一致、撤销条件不满足等）统一返回 409；参数校验失败返回 400。
